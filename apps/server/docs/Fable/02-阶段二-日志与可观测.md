# 阶段二：日志与可观测

> 目标：告别 `fmt.Println`，建立 zap 结构化日志；请求日志、登录日志入库，后台能查。
> 这是后台系统"排查问题"能力的基础，前端视角类比：相当于给后端装上 Sentry + 埋点。

## 任务 2.1 接入 zap 日志

1. 新建 `internal/pkg/logger/logger.go`：
   - 初始化 `zap.Logger`，暴露 `logger.Info / Warn / Error` 等全局方法
   - 支持从配置读取：日志级别、输出到控制台还是文件、文件路径
   - 用 `lumberjack` 做日志文件切割（按大小、保留天数）
2. 你已有 `config/autoload/logger.go`，把配置结构补全并接上。
3. 把项目里所有 `fmt.Println` 替换成 logger 调用（启动横幅可以保留）。

对照阅读：

```text
gin-layout/internal/pkg/logger/logger.go
gin-layout/config/autoload/logger.go
```

思考题：

- zap 的 `SugaredLogger` 和 `Logger` 有什么区别？gin-layout 用的哪个，为什么？
- 为什么生产环境日志要用 JSON 格式输出？

## 任务 2.2 请求日志中间件（打印版）

新建 `internal/middleware/logger.go`：

1. 请求进来记录开始时间；`c.Next()` 之后计算耗时。
2. 用 zap 记录：method、path、query、status、耗时、client IP、user-agent、uid（如果已登录）。
3. 替换掉 `gin.Default()` 自带的 `gin.Logger()`：改用 `gin.New()` + 自己的 logger 中间件 + recovery 中间件。
4. 同时自己写 `internal/middleware/recovery.go`：panic 时用 zap 记录堆栈，返回统一 500 JSON。

对照阅读：

```text

gin-layout/internal/middleware/recovery.go
gin-layout/internal/middleware/request_cost.go
```

思考题：

- 想记录响应 body 怎么办？（提示：看 gin-layout 的 `logger_recorder.go`，包装 `gin.ResponseWriter`）
- 为什么 recovery 中间件必须注册在最外层（最先 Use）？

## 任务 2.3 请求日志入库

1. 建表 `request_logs`（参考 gin-layout 迁移文件里的字段：method、path、query、body、status、cost、ip、uid、created_at 等）。
2. 新建 `internal/model/request_logs.go`。
3. 在日志中间件里，除了打 zap 日志，再把记录写入 MySQL。
4. **关键要求：写库不能阻塞请求、不能因为写库失败影响主流程。** 最小实现：起一个带缓冲 channel 的后台 goroutine 消费写库；channel 满了就丢弃并打 warn 日志。
5. 加接口 `GET /api/v1/request-log/list`（AuthPerm），支持按 path/uid/时间范围分页查询（分页可先简单实现，阶段三会统一重构）。

对照阅读：

```text
gin-layout/internal/middleware/logger_storage.go
gin-layout/internal/middleware/audit_queue.go（只看思想：异步+降级）
gin-layout/internal/model/request_logs.go
```

思考题：

- 同步写库、goroutine + channel、消息队列三种方案的取舍？gin-layout 为什么后来引入了 queue？
- 敏感字段（password）出现在请求 body 里，入库前要怎么处理？（看 gin-layout `internal/pkg/utils/desensitize.go`）

## 任务 2.4 登录日志

1. 建表 `admin_login_logs`：uid、username、ip、user-agent、登录结果（成功/失败）、失败原因、created_at。
2. 新建 `internal/model/admin_login_logs.go`。
3. 在登录 service 中，无论成功失败都记录一条（同样异步、不阻塞）。
4. 加接口 `GET /api/v1/login-log/list`（AuthPerm）。

对照阅读：

```text

gin-layout/internal/service/auth/login_log_helpers.go

```

## 晋级标准
