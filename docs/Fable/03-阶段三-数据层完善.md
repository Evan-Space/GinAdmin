# 阶段三：数据层完善（base 抽象、分页基建、迁移、Redis）

> 目标：消灭各个 service 里重复的分页/查询代码，建立可复用的数据层基建；
> 数据库结构改为迁移文件管理；接入 Redis 为阶段四做准备。

## 任务 3.1 model 基类抽象

现在每个 model 各写各的。参考 gin-layout 把公共能力下沉：

1. `internal/model/base.go`：公共字段（ID、CreatedAt、UpdatedAt、DeletedAt 软删除）、公共钩子、时间格式化输出。
2. `internal/model/base_crud.go`：通用的 Create / UpdateById / DeleteByIds / FindById。
3. 让 admin_user、role、menu 等 model 全部嵌入 base，删掉重复代码。

对照阅读：

```text
gin-layout/internal/model/base.go
gin-layout/internal/model/base_crud.go
```

思考题：

- GORM 软删除（`gorm.DeletedAt`）的原理是什么？查询时它是怎么自动加 `deleted_at IS NULL` 的？
- gin-layout 的时间字段为什么要自定义类型做 JSON 序列化？（前端拿到的时间格式问题，你应该很有体感）

## 任务 3.2 分页列表基建（本阶段核心）

这是后台系统写得最多的代码，一定要做成通用的：

1. 定义列表请求基础结构（`internal/validator/form/common.go` 扩展）：

```go
type ListQuery struct {
    Page     int    `form:"page,default=1"`
    PageSize int    `form:"page_size,default=20" binding:"max=200"`
    Sort     string `form:"sort"`   // 例: -created_at
    Keyword  string `form:"keyword"`
}
```

2. 新建 `internal/model/base_list.go`（或 `internal/pkg/query_builder/`）：
   - 输入：`*gorm.DB` + 分页参数 + 过滤条件
   - 输出：`{ list: [...], total: n, page: x, page_size: y }`
   - 支持：分页、排序白名单（防注入）、关键字模糊查询、时间范围
3. 用这套基建重写 admin_user / role / menu / request-log / login-log 的 list 接口，各 service 的 List 方法应缩到 10 行以内。

对照阅读：

```text
gin-layout/internal/model/base_list.go
gin-layout/internal/pkg/query_builder/query_builder.go
gin-layout/internal/pkg/request/request.go
```

思考题：

- 排序字段为什么必须做白名单校验？`?sort=-password` 或 SQL 注入会发生什么？
- `count(*)` 和取列表是两次查询，gin-layout 是怎么组织的？大表下 count 慢有什么优化思路？

## 任务 3.3 数据库迁移

告别手写 SQL 文件散落各处（现在的 `SQL/createTableDemoSql.sql`）：

1. 引入 `golang-migrate`（gin-layout 用的方案），建 `data/migrations/` 目录。
2. 把现有全部表整理成第一个迁移：`xxx_init_table.up.sql` / `.down.sql`。
3. 初始数据（超管账号、默认角色）做成第二个迁移 `xxx_init_data.up.sql`。
4. 加 cobra 子命令：`go run main.go migrate up` / `migrate down`。

对照阅读：

```text
gin-layout/data/migrations/
gin-layout/internal/console/migrate/migrate.go
gin-layout/docs/MIGRATE_COMMANDS.md
```

思考题：

- 为什么每个迁移都要写 down？什么场景会用到？
- 迁移文件名里的时间戳序号起什么作用？两个人同时开发怎么避免冲突？

## 任务 3.4 接入 Redis

1. 新建 `data/redis.go`：初始化 `go-redis` 客户端，纳入 `data.Initialize()` 和 `data.Shutdown()`。
2. 配置补充 `config/autoload/redis.go` 风格的 Redis 配置（host、port、db、password、pool）。
3. 做一个最小使用场景练手：把「用户信息」缓存 5 分钟（登录后 `GET /admin-user/get` 先查 Redis，未命中回源 MySQL 并写缓存；更新资料时删缓存）。

对照阅读：

```text
gin-layout/data/redis.go
gin-layout/config/autoload/redis.go
```

思考题：

- 「先更新 DB 再删缓存」和「先删缓存再更新 DB」各有什么问题？
- Redis 连接池参数（PoolSize、MinIdleConns）什么时候需要调？
