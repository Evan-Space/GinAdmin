# 阶段四：认证进阶（双 token、会话管理、黑名单、登录安全）

> 目标：把"能登录"升级为"生产级登录"。前置依赖：阶段三的 Redis。
> 前端视角类比：你平时对接的 access_token + refresh_token 无感刷新，这次自己实现服务端。

## 任务 4.1 双 token（access + refresh）

1. 登录返回改为：

```json
{
  "access_token": "...",   // 短期，如 2h
  "refresh_token": "...",  // 长期，如 7d
  "token_type": "Bearer",
  "expires_in": 7200
}
```

2. 新增 `POST /api/v1/refresh-token`（AuthNone）：用 refresh_token 换新的 access_token（可选：同时轮换 refresh_token）。
3. refresh_token 建议不用 JWT 而用随机串，存 Redis：`key = refresh:{token}`，value 含 uid、过期时间。

对照阅读：

```text
gin-layout/internal/service/auth/login.go
gin-layout/internal/service/auth/login_refresh.go
gin-layout/internal/service/auth/login_types.go
```

思考题：

- 为什么 access_token 要短、refresh_token 要长？各自泄露的风险和影响范围？
- refresh_token 轮换（用一次就换新）防的是什么攻击？

## 任务 4.2 登出与 token 黑名单

JWT 是无状态的，签出去就收不回 —— 除非加黑名单：

1. 新增 `POST /api/v1/logout`（AuthLogin）：
   - 把当前 access_token（或其 jti）写入 Redis 黑名单，TTL = token 剩余有效期
   - 删除对应 refresh_token
2. `ParseToken` 中间件解析成功后，多查一步黑名单，命中则视为未登录。

对照阅读：

```text
gin-layout/internal/service/auth/login_blacklist.go
gin-layout/internal/service/auth/login_revoke.go
```

思考题：

- 黑名单 TTL 为什么设成"token 剩余有效期"而不是永久？
- 每个请求都查一次 Redis，性能上可接受吗？有什么优化手段？

## 任务 4.3 会话管理（在线设备列表）

1. 登录时在 Redis 记录会话：uid → 该用户所有活跃 session（token 摘要、IP、UA、登录时间）。
2. 新增接口：
   - `GET /api/v1/session/list`（AuthPerm）：查看某用户的在线会话
   - `POST /api/v1/session/kick`（AuthPerm）：强制下线某个会话（本质是把它的 token 拉黑）
3. 可选策略：同一账号最多 N 个会话，超出踢掉最早的。

对照阅读：

```text
gin-layout/internal/service/auth/session.go
gin-layout/internal/controller/admin_v1/auth_session.go
```

## 任务 4.4 登录安全

1. **密码存储改造**：如果现在还是明文/简单哈希，改成 bcrypt（`golang.org/x/crypto/bcrypt`）。写迁移把存量密码处理掉。
2. **失败锁定**：同一账号连续失败 5 次，锁定 10 分钟（计数放 Redis，带 TTL）。
3. **图形验证码**（选做）：失败 3 次后要求验证码，参考 `gin-layout/pkg/utils/captcha/`。

对照阅读：

```text
gin-layout/internal/service/auth/login_security.go
gin-layout/internal/model/login_security_state.go
```

思考题：

- bcrypt 和 md5+salt 的本质区别？bcrypt 的 cost 参数控制什么？
- 按「账号」限失败次数和按「IP」限，各防什么场景？只做其一有什么漏洞？

## 晋级标准

```text
[ ] 登录返回双 token，refresh 接口可用，access 过期后可无感续期
[ ] 登出后原 access_token 立即失效（curl 验证 401）
[ ] 能查看和踢出在线会话，被踢会话的下一个请求 401
[ ] 密码 bcrypt 存储，登录接口有失败锁定
[ ] auth service 的核心逻辑（黑名单判断、锁定计数）有单元测试
```
